# window-order-bot

Разбор свободной заявки на окна/двери/стеклопакеты в структурированный вид (Telegram-бот + CLI).

## Как это устроено

Извлечение полей (тип изделия, ширина/высота в мм, количество, контакты) делает LLM через
[Groq](https://console.groq.com) (OpenAI-совместимый API, по умолчанию — бесплатная модель
`openai/gpt-oss-120b`, весь API у Groq бесплатный с лимитами по RPM): схема в
`src/schema.py` передаётся текстом в системном промпте, модели явно запрещено подставлять
значения по умолчанию — чего нет в тексте, то приходит как `null` и попадает в список
недостающих полей, а не придумывается. Поверх этого — чистый детерминированный Python
(`src/parser.py`): маска телефона (`+375 (29) 000-00-21`) и текст финального ответа собираются
кодом, а не моделью, чтобы формат не "гулял" от запроса к запросу. Если сообщение не заявка,
модель возвращает `is_order=false`, и бот отвечает, что это не похоже на заявку.

Бот помнит диалог в рамках одного чата (таймаут 20 минут на разговор) — но не как склейку сырого
текста всех сообщений подряд. Вместо этого модели на каждом шаге передаётся **текущее состояние
заявки** (JSON, уже извлечённое из предыдущих сообщений) плюс только новое сообщение, с явной
инструкцией обновить состояние: заменить то, что уточнено заново (например, новый телефон вместо
старого), и не трогать остальное. Это надёжнее, чем заново разбирать весь диалог каждый раз —
не дублирует изделия и не теряет уже известные контакты, если покупатель пишет что-то новое поверх
уже разобранной заявки. Заявка сохраняется только когда заполнены и изделие
(тип/размеры/количество), и хотя бы один контакт (телефон или email) — без контакта связаться
с покупателем всё равно нельзя, поэтому просто имени недостаточно, бот явно попросит телефон
или email. Пока чего-то не хватает, под сообщением есть кнопка «✅ Это всё, больше ничего не
добавлю» — досрочно завершает диалог и передаёт заявку как есть (менеджер увидит, что связаться
не с кем, если контактов так и не дали). Альтернативный способ — команда `/form`: пошаговая форма
кнопками (тип/единицы/размеры/количество/контакты) без свободного текста вообще; на выходе — та
же структура данных.

Готовые заявки пишутся в SQLite (`data/orders.db`, две таблицы — `orders` и `order_items`,
1 заказ → N изделий) через встроенный `sqlite3`, без отдельного сервера БД. Посмотреть их можно
`python view_orders.py` (без установки SQLite-клиента) либо `sqlite3 data/orders.db`. Незавершённые
диалоги (chat_data/user_data, включая шаги формы) переживают перезапуск бота через
`PicklePersistence` (`data/bot_state.pickle`). Папка `data/` — в `.gitignore`, в ней телефоны/имена
покупателей.

Голосовые, фото, стикеры и прочие не-текстовые сообщения бот пока не разбирает — отвечает,
что понимает только текст, и предлагает `/form`. При старте бот сам дёргает модель тестовым
запросом и пишет в лог, жива ли она — чтобы не узнавать об упавшем GROQ_API_KEY/модели только
по жалобе первого написавшего пользователя.

## Установка

```bash
cd window-order-bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # вписать GROQ_API_KEY и TELEGRAM_BOT_TOKEN
```

`GROQ_API_KEY` берётся на [console.groq.com/keys](https://console.groq.com/keys) (кнопка
Create API Key) — платёжные данные не нужны.

## Запуск

CLI (без Telegram, для быстрой проверки — печатает разбор трёх примеров из задания):

```bash
cd src && python cli.py --demo
```

Разбор одной произвольной фразы:

```bash
cd src && python cli.py "Нужно окно 1000х1200, 2 шт. Павел, +375 29 000-00-21"
```

Telegram-бот (нужен `TELEGRAM_BOT_TOKEN` от @BotFather):

```bash
cd src && python bot.py
```

Либо через готовый скрипт — сам останавливает прошлый запущенный процесс (если был) и
поднимает новый в фоне с логом в `data/bot.log`:

```bash
./restart_bot.sh
```

(У меня локально поверх этого ещё сделан `.desktop`-ярлык на рабочий стол — он привязан
к конкретному пути на моей машине, поэтому в репозиторий не включён.)

Просмотр сохранённых заявок:

```bash
cd src && python view_orders.py        # последние 20, можно python view_orders.py 100
```

Тесты (чистые функции `parser.py` + `storage.py` на временной БД; без сети и без API-ключа):

```bash
pip install -r requirements-dev.txt
pytest tests/
```

## Структура

```
src/
  schema.py     — JSON-схема для LLM (контракт "ничего не выдумывать")
  parser.py     — вызов модели, маска телефона, сборка текста ответа
  storage.py    — SQLite-хранилище заявок (data/orders.db)
  view_orders.py — просмотр сохранённых заявок из консоли
  wizard.py     — пошаговая форма по кнопкам (/form), альтернатива свободному тексту
  bot.py        — Telegram-бот (python-telegram-bot)
  cli.py        — локальный прогон без Telegram
tests/
  test_parser.py  — тесты normalize_phone() и format_response()
  test_storage.py — тесты записи/чтения заявок (на временной БД)
```
