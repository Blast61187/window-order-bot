# window-order-bot

Разбор свободной заявки на окна/двери/стеклопакеты в структурированный вид (Telegram-бот + CLI).

## Как это устроено

Извлечение полей (тип изделия, ширина/высота в мм, количество, контакты) делает LLM через
[Groq](https://console.groq.com) (OpenAI-совместимый API, по умолчанию — бесплатная модель
`openai/gpt-oss-120b`, весь API у Groq бесплатный с лимитами по RPM): схема в
`src/schema.py` передаётся текстом в системном промпте, модели явно запрещено подставлять
значения по умолчанию — чего нет в тексте, то приходит как `null` и попадает в список
недостающих полей, а не придумывается. Поверх этого — чистый детерминированный Python
(`src/parser.py`): маска телефона (`+375 (29) 000-00-21`) и текст финального ответа собираются
кодом, а не моделью, чтобы формат не "гулял" от запроса к запросу. Если сообщение не заявка,
модель возвращает `is_order=false`, и бот отвечает, что это не похоже на заявку.

Бот помнит диалог в рамках одного чата (скользящее окно последних сообщений, таймаут 20 минут),
поэтому ответ на уточняющий вопрос («3 штуки, +375 29 000-00-21») подхватывается как продолжение
той же заявки, а не разбирается отдельно. Пока бот ждёт уточнения, под сообщением есть кнопка
«✅ Это всё, больше ничего не добавлю» — досрочно завершает диалог и передаёт заявку как есть.
Альтернативный способ — команда `/form`: пошаговая форма кнопками (тип/единицы/размеры/
количество/контакты) без свободного текста вообще; на выходе — та же структура данных.

Готовые заявки пишутся в `data/orders.jsonl` (по одной на строку, JSON) — для просмотра
менеджером. Незавершённые диалоги (chat_data/user_data, включая шаги формы) переживают
перезапуск бота через `PicklePersistence` (`data/bot_state.pickle`). Папка `data/` — в
`.gitignore`, в ней телефоны/имена покупателей.

Голосовые, фото, стикеры и прочие не-текстовые сообщения бот пока не разбирает — отвечает,
что понимает только текст, и предлагает `/form`. При старте бот сам дёргает модель тестовым
запросом и пишет в лог, жива ли она — чтобы не узнавать об упавшем GROQ_API_KEY/модели только
по жалобе первого написавшего пользователя.

## Установка

```bash
cd window-order-bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # вписать GROQ_API_KEY и TELEGRAM_BOT_TOKEN
```

`GROQ_API_KEY` берётся на [console.groq.com/keys](https://console.groq.com/keys) (кнопка
Create API Key) — платёжные данные не нужны.

## Запуск

CLI (без Telegram, для быстрой проверки — печатает разбор трёх примеров из задания):

```bash
cd src && python cli.py --demo
```

Разбор одной произвольной фразы:

```bash
cd src && python cli.py "Нужно окно 1000х1200, 2 шт. Павел, +375 29 000-00-21"
```

Telegram-бот (нужен `TELEGRAM_BOT_TOKEN` от @BotFather):

```bash
cd src && python bot.py
```

Тесты (чистые функции `parser.py` — маска телефона, сборка ответа; без сети и без API-ключа):

```bash
pip install -r requirements-dev.txt
pytest tests/
```

## Структура

```
src/
  schema.py   — JSON-схема для LLM (контракт "ничего не выдумывать")
  parser.py   — вызов модели, маска телефона, сборка текста ответа
  storage.py  — запись готовых заявок в data/orders.jsonl
  wizard.py   — пошаговая форма по кнопкам (/form), альтернатива свободному тексту
  bot.py      — Telegram-бот (python-telegram-bot)
  cli.py      — локальный прогон без Telegram
tests/
  test_parser.py — тесты normalize_phone() и format_response()
```
